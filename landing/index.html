Local search CLI and MCP server for coding agents · one Rust binary · Apache-2.0

Ask a GitHub repo a question. Get the file and line.

XERJ is open-source search for AI agents. xerj "question" routes your question through a signed catalogue of pre-indexed open-source projects (14 today, from the Corpus Hub) to one corpus pack, downloads that pack once from GitHub Releases, and answers on a search node on your own machine, with the file, the line, the pinned commit and the licence. xerj autoindex <folder> does the same for your own files. Agents reach it from a shell, over MCP, or with any Elasticsearch client.

Install · Linux and macOS · SHA-256 verified, fail-closed curl -fsSL https://xerj.org/get | sh
Or hand this to your coding agent Install XERJ (docs: https://xerj.org/llms.txt). Before you write code against a library you do not know well, ask it with xerj "<question>" and cite the file:line it returns. Index this project with xerj autoindex . and search it instead of reading files one by one.

Windows: irm https://xerj.org/get.ps1 | iex. Prebuilt for Linux, macOS and Windows on x86_64 and arm64; Linux builds are static musl. All targets and the manual verified install. The copied prompt also asks the agent to send one field report when it is done; the text says how to opt out.

Three ways in

Ask a library, search your folder, or connect over MCP

01 · Ask a hub corpus

Library questions without cloning

For code you have not memorised: a library's source at a pinned commit, a spec, an advisory feed. The router picks one corpus from the signed catalogue; --corpus skips routing, --def asks for one definition.

xerj "how does zstd pick a window size"
xerj ask --def ZSTD_compressBound
xerj ask reference → 02 · Index your own folder

Your repo, docs and data, searchable

One command sniffs every file by content: code through tree-sitter with symbols and line numbers, plus PDF, DOCX, SQLite, CSV, mail, logs. Nothing leaves the machine.

xerj --insecure --data-dir ~/xerj-data &
xerj autoindex ~/my-project
xerj search "how do we rotate the WAL segment"

Corpus Hub · hub.xerj.org

Reference memory, pinned and licence-checked

The Corpus Hub is the registry behind xerj ask. Each corpus is a field's open material pinned to one commit: library source, standards, advisory feeds, detection rules. Each corpus page shows its human licence review and whether its retrieval has been graded against five pre-registered questions. Packs are built in CI, signed with ed25519 and published as GitHub Releases; the client verifies the signature and the SHA-256 before it restores a pack.

On the hub today513 live corpora in 11 domains, 78.6 GB of pinned text (hub.xerj.org, fetched 2026-10-19)
Routed by xerj ask14 corpora in the signed catalogue the CLI downloads (generated 2026-10-18), including lz4, zstd, snappy, aiohttp and alertmanager
Licence classesadapt-with-attribution (permissive and public-domain sources) or approach-only (GPL-family: read for the design, do not copy). Closed standards are excluded.
ContributorsContributor pages list who made each corpus possible; hub stars from visitors are kept apart from GitHub stars, and each corpus card shows its agent A/B result (bare against with-corpus pass counts) on its own. Sign in with GitHub or Hugging Face.
UsageRequests agents send to the hosted hub API are counted for 30 days; local queries are not counted.

Use cases

What agents point it at

Reference coding

Retrieve how the open-source projects closest to your task solved it, then write the code. The measured use case: 2.7× fewer output tokens than grep.

Case study → Code-security audits

Index a target tree once and query for sinks, secrets and dangerous calls across every file type. WordPress core: 1,492 PHP files on about 26,000 tokens.

Audit write-up → Search a folder of files

Code, PDFs, Word documents, mailboxes and SQLite in one index. The search itself runs no model, so it spends no tokens.

Zero-token search → Agent memory

/_memory/<namespace> stores what an agent learns and recalls it next session, isolated per namespace.

Memory and links → RAG retrieval

BM25, kNN and hybrid in one query. The default embedder is lexical feature-hashing; neural is opt-in with --embed-mode neural.

AI search → Elasticsearch-compatible search

The REST API on :9200 speaks the Elasticsearch wire protocol for indices, bulk, search, aggregations, kNN and scroll, on a single node.

Before you rely on it

When XERJ does not help

  • Libraries the model already knows. Retrieval wins on private, niche or post-cutoff code and is neutral to harmful on popular public libraries, where it only adds cost (limits section of the case study).
  • "Semantic" is lexical by default. The built-in embedder is feature-hashing over words and sub-words, not a neural model. Start the node with --embed-mode neural for real semantics (about 90 MB downloaded on first use).
  • One node. XERJ runs single-node. There is no replication or failover. When to choose Elasticsearch instead: you need a replicated cluster, or steady read p99 under a heavy concurrent write load, which is where all four of its benchmark wins came from (benchmarks).
  • --insecure is for one user on one machine. It turns off TLS and API-key auth. A fresh node binds 127.0.0.1 only; see the security model.

Community

Run it, then send one field report

The project asks one thing in return for the binary: a short report of what you pointed it at and your honest verdict. A negative verdict is a good report. xerj feedback --submit opens the pull request for you, or an agent calls the xerj_field_report MCP tool. Field-report pull requests need no CLA signature.
